# 知库 Roadmap

> 本文记录当前能力的边界与后续优先级，判断依据是「一个企业内部知识库要真正可用，还缺什么」。

---

## 现状评估

| 维度 | 现状 | 结论 |
| --- | --- | --- |
| 入库链路 | PDF / Word(.docx) / Markdown / TXT → 解析 → 切分(1000/20) → 向量化 → Neo4j | 可用 |
| 检索 | 向量 top2k ∪ 全文，RRF k=60 融合；图谱证据补充 | 可用，缺重排 |
| 编排 | 规划 → 检索 → 可答性评估 → 证据融合 → 带来源作答（SSE） | 可用 |
| 权限 | 按 `user_id` 隔离（个人库） | **缺部门/密级 ACL** |
| 评测 | 有 Recall/MRR/nDCG 与 LLM 裁判脚本 | **缺固定基线数字与 CI 门禁** |
| 可观测 | 结构化日志 + 分阶段耗时 | **缺 trace 与成本台账** |
| 安全 | 只读工具、限流、JWT、检索带用户过滤 | 缺注入测试与审计 |
| 工程化 | 637 单测、ruff、类型构建 | 缺 CI |

## 优先级

### P0 · 让效果可被证明

1. **评测基线**
   固定 60–120 条分层样本（事实 / 跨文档冲突 / 多跳 / 无答案 / 多轮），跑出 Recall@5、nDCG@10、faithfulness、引用覆盖率、P95 延迟、单查询成本，结果提交到 `evals/results/`。
   *验收*：一条命令出报告，README 指标表有真实数字。

2. **检索期 ACL**
   `documents` 表记录 `dept / visibility / sensitivity`，随 chunk 落入 Neo4j；在 `search_chunks` 的 Cypher 里做 **pre-filter**（不是检索后再筛），覆盖「企业公共 / 部门 / 个人」三级可见性。
   *验收*：越权用例 0 命中；审计日志可查「谁看过哪份文档」。

3. **可观测性**
   接入 OpenTelemetry + Langfuse（自托管），把 `plan / retrieve / rerank / evaluate / answer` 拆成 span；每次请求落一行 `request_metrics`（TTFB、总耗时、token、成本、空召回）。
   *验收*：凭 trace_id 能把一次坏回答归因到具体阶段。

### P1 · 让系统更像「工程产品」

4. **Rerank 对照实验**：召回 20 → 重排 → 取 5，与纯 RRF 对比 nDCG 与延迟，按场景开关（`ReorderService` 已实现，尚未接入主链路）。
5. **安全回归**：提示词套取、越权列举、来源混淆、间接注入等 15–20 条用例，接入 CI。
6. **CI 门禁**：GitHub Actions 跑 ruff + pytest + 前端构建；评测冒烟（小样本）在 PR 上跑，完整评测 nightly。
7. **成本与缓存**：query 向量缓存、重复问题答案缓存（带权限指纹与 TTL）、规划/评估走小模型。

### P2 · 按需推进

| 项 | 价值 | 备注 |
| --- | --- | --- |
| MCP Server | 把检索/图谱查询暴露为 MCP 工具，编辑器与 Agent 可直接接入 | 协议层能力，工作量中等 |
| 反馈闭环 | 答案 👍/👎 → badcase 池 → 加入评测集 → 回归 | 数据驱动迭代的基础 |
| 增量索引 | 文档变更只重建受影响 chunk | 长文档库必需 |
| 结构化切分 | 按标题层级切，对比召回变化 | 需配合评测验证 |
| 管理后台 | 上传审核、下线、版本、部门与成员管理 | 企业落地的必要配套 |

**暂不做**：多 Agent 编排、自主循环、图谱可视化。当前任务边界清晰，这些会显著增加不确定性而不带来可验证收益。

## 六周计划

| 周 | 目标 | 产物 |
| --- | --- | --- |
| W1 | 评测基线 | 分层样本集、一键评测、基线报告 |
| W2 | 检索优化 | rerank 开关 + 三种策略对照数据 |
| W3 | 权限 | documents 表、chunk ACL、Cypher pre-filter、越权用例 |
| W4 | 可观测 | Langfuse 接入、指标表、trace 截图 |
| W5 | 安全 + CI | 注入用例、Actions 流水线、质量门禁 |
| W6 | 收尾 | README 指标回填、演示脚本、部署验证 |

## 已知限制

- 仅支持 `.docx`，不支持旧版 `.doc`；扫描版 PDF 无 OCR，文本为空的文档会被明确跳过。
- 检索为同步调用，超大文档库需要引入异步任务与索引分片。
- 单实例部署；横向扩展需要把 worker 与 API 拆开，并引入队列背压。
