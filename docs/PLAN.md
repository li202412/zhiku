### 3.1 阶段 2 设计要点（可见性前置过滤）

```cypher
// 目标形态：过滤条件进索引层，而不是取回后再筛
MATCH (node:Chunk)
  SEARCH node IN (VECTOR INDEX chunk_embedding_index FOR $embedding LIMIT $k)
  WHERE node.user_id = $uid
    AND (node.visibility = 'shared' OR node.owner_id = $uid)
RETURN node, score
```

- **必须前置**：权限要在进入模型上下文之前完成，不能「先检索再让模型别说」。
- **版本前提**：`db.index.vector.queryNodes` 在 Neo4j 2026.09 已弃用，其 `WHERE` 是取回 k 个候选后才过滤，候选被大量滤掉会导致召回塌陷；要么用 `SEARCH`（真前置），要么放大 `pool` 补偿并在文档写明这是补偿。
- **兼容要求**：默认参数下行为与现状一致（637 测试不能崩）；缺失属性的旧数据按「私有、仅 owner 可见」处理。

## 七、风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Docker 镜像构建受阻（网络/torch 体积大） | 部署叙事缺证据 | 已搁置；本地方式跑通即可，投递后再补 |
| 评测数字仍不可对外（密度、自评） | 无法声明绝对值 | 报相对提升 + 口径限定；必要时人工抽检 50 条交叉验证 |
| `SEARCH` 与现有索引不兼容 | 可见性退化为放大 pool 补偿 | 先做最小实验验证可行性与召回损失 |
| 时间被压缩 | 阶段 5、6 仓促 | 保 M1、M2；CI 降级为「ruff + pytest」最小门禁 |
